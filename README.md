# Bio-Dosha-12

**Биеийн тэнцвэрийн хяналт** — Монгол уламжлалт анагаах ухааны махбодын онолыг
(Хий · Шар · Бадган) орчин үеийн тооцооллын аргатай хослуулсан веб апп.
Хэрэглэгч төрөлхийн махбодоо нэг удаа тодорхойлоод, өдөр тутмын жингээрээ
биеийн тэнцвэрийн **BEDI индексээ** хянаж, тохирсон зөвлөмж (ерөндөг) авна.

## Гол боломжууд

- **Махбодын үнэлгээ** — 12 асуулттай сорил. Асуулт бүр **хөдөлгөөнт дүрслэлтэй
  тусламжийн карттай**: «Хэрхэн тодорхойлох вэ?» товчоор тухайн шинжийг бодитоор
  шалгах аргыг (жишээ нь ясны хэмжээний **бугуйн сорил** — бугуйгаа атгаад эрхий,
  долоовор хурууны нийлэлтийг харах) гурван үр дүнгийн төлөвтэй нь үзүүлнэ.
  Хариулт дээр дарвал зураг тухайн төлөвт царцана; `prefers-reduced-motion`
  тохиргоог хүндэтгэнэ.
- **BEDI тооцоолуур** — жин, өндөр, нас, улирал, махбодын Kt коэффициентыг
  нэгтгэсэн тэнцвэрийн индекс, хазайлтын луужин, түүхийн график.
- **Ерөндөг зөвлөмж** — хазайлт болон насны онцлогт тохирсон хоол хүнс,
  дэглэмийн зөвлөмж.
- **Гэр бүлийн профайл** — гишүүн бүрд тусдаа үнэлгээ, хяналт.
- **Эмнэлэг, байгууллага** — эмнэлэг бүртгүүлж, платформ баталгаажуулсны дараа
  эзэн, эмч нар байгууллагын өвчтөний бүртгэл, үзлэгийн карт, эмчилгээний хуудас,
  кирилл үсэгтэй PDF тайланг хамтран хөтөлнө. Гишүүдийг урилгаар нэмнэ (эзэн, менежер, эмч).
  Дэлгэрэнгүй: [docs/clinical-intake-setup.md](docs/clinical-intake-setup.md).
- **Удирдлагын төв** (`/admin`) — байгууллага баталгаажуулах, түр хаах, хэрэглэгчийн
  дэмжлэг, багц оноох, урилга, аудитын бүртгэл, системийн шалгалт. Платформын ажилтан
  эрүүл мэндийн бүртгэлийг **харахгүй**.
- **Багц (tier)** — хувь хүн, байгууллагад зориулсан багц, хязгаар. Төлбөрийн систем
  дараа нь `src/lib/subscriptions.ts`-ээр холбогдоно.
- **Мэдээллийн хамгаалалт** — мэдрэг талбаруудын AES-256-GCM шифрлэлт, ажилтан болон
  байгууллагын гишүүдэд 2 шаттай нэвтрэлт (TOTP), нэг удаагийн урилга/сэргээх холбоос,
  аудитын бүртгэл, өөрийн мэдээллээ татах, бүртгэлээ устгах.

Архитектур, эрхийн загвар, API: [docs/platform-architecture.md](docs/platform-architecture.md).
Production-д нэвтрүүлэх заавар: [docs/deployment-checklist.md](docs/deployment-checklist.md).

## Технологи

| Давхарга | Сонголт |
|---|---|
| Framework | Next.js 16 (App Router, Turbopack), React 19, TypeScript |
| Загвар | Tailwind CSS v4 (CSS-first токенууд), shadcn / Base UI, Material Symbols |
| Өгөгдөл | PostgreSQL + Prisma 7 (`prisma/schema.prisma`) |
| Нэвтрэлт | NextAuth v5 (credentials), `src/proxy.ts` (Next 16-д middleware-ийн шинэ нэр) |
| Бусад | next-intl (MN/EN chrome), recharts, @react-pdf/renderer, vitest |

> төслийн Next.js хувилбарын онцлогуудыг `node_modules/next/dist/docs/`-оос
> шалгах шаардлагатай.

## Хөгжүүлэлтийн орчин

```bash
npm install                 # postinstall нь prisma generate ажиллуулна

# Орчны хувьсагчид (.env):
#   DATABASE_URL="postgresql://user:pass@localhost:5432/biodosha"
#   AUTH_SECRET="ямар нэг нууц тэмдэгт мөр"
#   AUTH_TRUST_HOST=true    # локал орчинд
#   ENCRYPTION_KEY="..."    # node -e "console.log(require('crypto').randomBytes(32).toString('base64'))"
#   APP_URL="http://localhost:3000"   # урилга, нууц үг сэргээх холбоосын хаяг
#   RESEND_API_KEY, EMAIL_FROM        # заавал биш: имэйлээр илгээх бол

npx prisma migrate deploy   # эсвэл: npx prisma migrate dev
npx tsx scripts/bootstrap-superadmin.ts you@example.mn --apply   # супер админы урилга
npm run dev                 # http://localhost:3000
```

Хувь хүн `/register` хуудсаар бүртгүүлнэ (Нууцлалын бодлогыг зөвшөөрөх, нууц үг ≥ 8
тэмдэгт). Эмнэлэг «Байгууллага» төрлөөр бүртгүүлэхэд «Хүлээгдэж буй» төлөвтэй үүснэ;
удирдлагын төвд баталгаажуулсны дараа өвчтөний бүртгэл нээгдэнэ. Супер админы эрхийг
орчны хувьсагчаар биш, зөвхөн `scripts/bootstrap-superadmin.ts`-ээр үүсгэнэ.

### Аюулгүй байдал

- Нэвтрэлт: имэйл тус бүрд 15 минутад 10, IP тус бүрд 50 оролдлого; бүртгэл IP тус бүрд цагт 10.
  Тоолуур нь `RateLimit` хүснэгтэд хадгалагдана (гадны үйлчилгээгүй).
- Session 12 цагийн дараа дуусна. Security header-ууд (CSP, X-Frame-Options г.м) `next.config.ts`-д.
- Мэдрэг талбарууд (үзлэгийн тэмдэглэл, онош, судасны хүснэгт, регистр, утас, хаяг,
  TOTP нууц) `ENCRYPTION_KEY`-ээр шифрлэгдэнэ; түлхүүргүй үед уншихаас татгалзана.
- Платформын ажилтан, байгууллагын гишүүд 2 шаттай нэвтрэлтийг заавал ашиглана.
- Аудитын бүртгэл хэн, юуг, хэзээ хийснийг (эрүүл мэндийн агуулгагүйгээр) хадгална.
- Эмч өвчтөний бүх мэдээллийг өвчтөний хуудаснаас бүрмөсөн устгах боломжтой.

### Хадгалсан BEDI бичлэгийг дахин тооцоолох

```bash
DATABASE_URL=... npx tsx scripts/recompute-bedi.ts           # зөвхөн урьдчилан харна
DATABASE_URL=... npx tsx scripts/recompute-bedi.ts --apply   # нөөц JSON үүсгээд бичнэ
```

Нөөц файл (`bedi-backup-*.json`) эрүүл мэндийн мэдээлэлтэй тул git-д орохгүй;
шалгаж дууссаны дараа устгана уу.

### Скриптүүд

| Команд | Үйлдэл |

| `npm run dev` | Хөгжүүлэлтийн сервер |

## Кодын бүтэц (товч)

```
src/
  app/            # App Router: (app)/ = нэвтэрсэн хэсэг, api/ = route handlers
  components/     # UI компонентууд
    help/         # Асуултын тусламжийн карт + 12 хөдөлгөөнт SVG дүрслэл
    ui/           # shadcn/Base UI суурь элементүүд
    clinical/     # Эмчийн горимын маягтууд
  lib/            # Инженерүүд: questionnaireEngine, bediEngine, remedyEngine,
                  # questionHelp (сорилын тусламжийн агуулга), glossary г.м.
  proxy.ts        # Auth middleware (Next 16 нэршил)
prisma/           # Схем ба миграцууд
docs/             # Нэмэлт баримтууд
```

Тусламжийн хөдөлгөөнт дүрслэлийн архитектур, шинэ карт нэмэх заавар:
[docs/help-illustrations.md](docs/help-illustrations.md).

## Судалгааны үндэслэл ба анхааруулга

BEDI аргачлал нь «Төмөрбаатар Оточ» эмнэлэгт 2023–2025 онд хийгдсэн 400 өвчний
түүх хамарсан судалгаагаар баталгаажсан (эмчийн оноштой 81% нийцэл, p < 0.01).
Энэхүү систем нь эмчийн үзлэг, оношилгоог орлохгүй — зөвлөмжийг хэрэгжүүлэхийн
өмнө мэргэжлийн эмчтэй зөвлөлдөнө үү.
